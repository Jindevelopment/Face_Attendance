# FaceGate — 얼굴로 출석 체크하는 시스템

> 카메라 앞에 서면 **"진짜 사람인지"** 확인하고, **"우리 조직에 등록된 누구인지"** 찾아서 출석을 기록합니다.

---

## 1. 이게 뭐예요?

학교나 학원에서 출석 부를 때를 떠올려 보세요. 이름을 부르면 "네!" 하고 대답하죠.
그런데 친구가 대신 대답하는 **대리 출석**이 문제입니다.

FaceGate는 얼굴로 출석을 부릅니다. 그런데 얼굴도 속일 수 있어요:

| 속이는 방법 | 예시 |
|---|---|
| 사진 들이대기 | 친구 사진을 인쇄해서 카메라에 보여주기 |
| 폰 화면 보여주기 | 친구 셀카를 폰에 띄워서 카메라에 대기 |
| AI로 얼굴 만들기 | 진짜 같은 가짜 얼굴 이미지 만들기 |

그래서 FaceGate는 **얼굴을 알아보기 전에, 진짜 사람인지부터 확인**합니다.
문이 두 개인 셈이에요. **첫 번째 문 = 진짜 사람인가**, **두 번째 문 = 등록된 사람인가.**

---

## 2. 누가 어떻게 쓰나요?

사람이 **두 종류**입니다.

```
 관리자                        참여자
 (선생님·강사·팀장)             (학생·수강생·팀원)
   │                             │
   │ 조직을 만든다                │
   │ → 인증코드 8자리 나옴  ──────▶ 코드를 받는다
   │                             │
   │                             │ 회원가입 + 코드 입력
   │                             │ → 그 조직에 참여
   │                             │
   │                             │ 얼굴을 한 번 등록
   │                             │
   │ 출석 현황을 본다      ◀──────  카메라 앞에 서면 출석
```

**인증코드가 문지기입니다.** 코드를 모르면 그 조직에 들어올 수 없고,
조직이 다르면 **서로의 데이터가 전혀 보이지 않습니다.**

### 화면 목록

| 주소 | 하는 일 | 누가 |
|---|---|---|
| `/` | 첫 화면 — 관리자/참여자 갈림길 | 누구나 |
| `/admin/signup` | 관리자 회원가입 (= 조직 만들기) | 누구나 |
| `/admin/login` | 관리자 로그인 | 누구나 |
| `/admin/dashboard` | 출석 현황·이상 탐지 기록 | 관리자 |
| `/admin/members` | 등록된 사람 목록 + 직접 등록 | 관리자 |
| `/admin/settings` | 인증코드 확인·재발급 | 관리자 |
| `/join` | 참여자 회원가입 (① 계정 → ② 코드) | 누구나 |
| `/login` | 참여자 로그인 | 누구나 |
| `/attendance` | 출결 체크 | 조직원 |
| `/me` | 내 얼굴 등록 + 내 출석 기록 | 조직원 |
| `/start` | 로그인했는데 조직이 없을 때 | 조직원 |

## 3. 출석은 어떻게 판정되나요?

출결 체크 버튼을 누르면 이런 일이 순서대로 일어납니다.

```
 ① 고개 돌리기 시험      "왼쪽으로 돌려주세요" → "이번엔 오른쪽으로"
     ↓                    순서는 매번 랜덤! 사진은 고개를 못 돌립니다.
 ② 컴퓨터가 1차 검사      눈 깜빡임, 화면 무늬 같은 걸 브라우저에서 빠르게 확인
     ↓
 ③ 서버가 2차 검사        AI 모델(MiniFASNet)이 "진짜 얼굴 맞나?" 판정
     ↓
 ④ 누구인지 찾기          같은 조직 사람들과만 비교해서 가장 비슷한 사람 찾기
     ↓
 ⑤ 출석 기록!            데이터베이스에 저장
```

**중간에 하나라도 실패하면 거기서 멈춥니다.** 그리고 "왜 실패했는지"를 기록해 둡니다.

### 얼굴을 어떻게 숫자로 비교하나요?

사람 얼굴을 **숫자 512개**로 바꿉니다. 키·몸무게·발 크기처럼, 얼굴의 특징을 숫자로 적어두는 거예요.

```
최진혁의 얼굴  →  [0.12, -0.87, 0.45, ... ]   ← 숫자 512개
방금 찍은 얼굴  →  [0.13, -0.86, 0.44, ... ]   ← 숫자 512개
                    ↑ 거의 같죠? = 같은 사람!
```

두 숫자 묶음이 얼마나 다른지를 **거리**로 잽니다. 0에 가까울수록 같은 사람이에요.

| 실제로 측정한 값 | 거리 |
|---|---|
| 본인 얼굴 | **0.025** ← 아주 가까움 |
| 본인 얼굴 (다른 날) | **0.029** |
| 폰 화면으로 보여준 사진 | **0.305** ← 멀다 |

그래서 **0.25보다 가까우면 같은 사람**으로 판정합니다. (자세한 이유는 §8)

## 4. 실행하기 (내 컴퓨터에서)

프로그램이 **3개** 필요합니다.

```
 [1] 데이터베이스 (Supabase)   ← 인터넷에 있음. 가입만 하면 됨
 [2] 얼굴 인식 서버 (Python)   ← 내 컴퓨터에서 실행
 [3] 웹사이트 (Next.js)        ← 내 컴퓨터에서 실행
```

### 4-1. 데이터베이스 준비 (Supabase)

1. [supabase.com](https://supabase.com) 가입 → 새 프로젝트 만들기
2. 왼쪽 메뉴 **SQL Editor** 에서 아래 파일들을 **번호 순서대로** 붙여넣고 실행

   | 파일 | 하는 일 |
   |---|---|
   | `supabase/migrations/0001_init.sql` | 표 만들기 + 얼굴 검색 기능 |
   | `supabase/migrations/0002_auth.sql` | 로그인 기반 |
   | `supabase/migrations/0003_organizations.sql` | 조직·인증코드 |
   | `supabase/migrations/0004_fix_ambiguous_org_id.sql` | 참여 오류 수정 |

3. **Project Settings → API** 에서 열쇠를 복사

> ⚠️ **열쇠 복사할 때 주의**
> 화면에 `sb_secret_••••••` 처럼 가려져 있습니다. 마우스로 드래그하면 **보이는 부분만 복사**돼서
> 잘린 열쇠가 붙여넣어집니다. 반드시 **복사 아이콘**을 누르거나 **Reveal**로 먼저 펼치세요.

### 4-2. 비밀 설정 파일 만들기

```cmd
copy .env.example .env.local
```

`.env.local` 을 열어서 값을 채웁니다.

```ini
NEXT_PUBLIC_SUPABASE_URL=https://여기에-내-프로젝트-주소.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=여기에-anon-키
SUPABASE_SERVICE_ROLE_KEY=여기에-service_role-키
ATTENDANCE_TOKEN_SECRET=여기에-랜덤-문자열-32자-이상
```

마지막 값은 아래 명령으로 만듭니다.

```cmd
node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"
```

> 🔑 **열쇠 3종류를 헷갈리지 마세요.** 여기서 잘못 넣는 실수가 가장 흔합니다.
>
> | 이름 | 생김새 | 용도 |
> |---|---|---|
> | anon | `eyJ...` (긺) | 브라우저용. 남이 봐도 괜찮음 |
> | service_role | `sb_secret_...` | 서버용. **절대 공개 금지** |
> | Personal Access Token | `sbp_...` | 내 계정 전체용. **여기에 쓰는 게 아님** |
>
> `.env.local` 은 절대 깃에 올리면 안 됩니다 (`.gitignore`에 이미 등록돼 있음).

### 4-3. 얼굴 인식 서버 실행 (Python)

> ⚠️ **반드시 Python 3.11을 쓰세요.** 3.12 이상에서는 torch가 설치는 되지만 **실행이 안 됩니다.**
> (실제로 3.14로 만들었다가 `Failed to load PyTorch C extensions` 오류로 막혔습니다.)

> ✅ **이미 설치돼 있다면 마지막 줄만 실행하세요.**
> `deepface-api\.venv\Scripts\python.exe --version` 이 `Python 3.11.x` 면 준비 완료입니다.

```cmd
cd deepface-api
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install torch==2.4.1 --index-url https://download.pytorch.org/whl/cpu
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py
```

> 💡 **`activate` 를 안 쓰는 이유**: cmd와 PowerShell은 활성화 명령이 서로 다릅니다.
> `.venv\Scripts\python.exe` 를 직접 부르면 어느 창에서든 똑같이 동작해서 실수가 없습니다.

처음 실행하면 AI 모델을 자동으로 내려받습니다(약 100MB, 몇 분 걸림).
`Running on http://127.0.0.1:5005` 가 보이면 성공입니다. **이 창은 닫지 마세요.**

### 4-4. 웹사이트 실행 (Next.js)

**새 명령 창을 하나 더 열고:**

```cmd
npm install
npm run dev
```

브라우저에서 **http://localhost:3000** 접속.

> 📷 카메라는 `localhost` 또는 `https://` 에서만 작동합니다. 브라우저 보안 규칙이에요.

### 4-5. 첫 조직 만들기

`/admin/signup` 에서 **조직 이름 + 이메일 + 비밀번호**를 넣으면 끝입니다.
가입하는 순간 그 조직의 관리자가 되고 **인증코드 8자리**가 나옵니다.

> 예전에는 여기서 SQL을 직접 실행해야 관리자가 됐습니다. 지금은 필요 없습니다.
> 조직별로 데이터가 갈리므로, 가입자는 **자기가 만든 조직만** 봅니다.

### 4-6. 참여자 초대

인증코드를 알려주면 `/join` 에서 가입합니다.

```
① 계정 만들기   이메일 + 비밀번호
② 인증코드      받은 8자리 코드  →  조직 참여 완료
```

그다음 `/me` 에서 얼굴을 한 번 등록하면 준비 끝입니다.

> ⏳ **가입할 때 메일이 안 가면** → §5 를 보세요. Supabase 기본 메일은 하루 몇 통 수준이라
> 금방 막힙니다.

## 5. 확인 메일 설정 (SMTP)

가입할 때 Supabase가 확인 메일을 보냅니다. 기본 설정으로는 금방 막히므로 별도 설정이 필요합니다.
자세한 절차는 **[`supabase/SMTP.md`](supabase/SMTP.md)** 에 있습니다.

**빠르게 정리하면:**

| 상황 | 할 일 |
|---|---|
| 혼자 개발/테스트 중 | Supabase에서 **Confirm email 끄기**. 메일이 아예 안 나갑니다. 인증코드가 문지기 역할을 그대로 하므로 위험이 작습니다. |
| 남을 초대해야 함 | **Resend + 내 도메인** 인증이 필요합니다. 도메인 없이 쓰는 `onboarding@resend.dev` 는 **내 계정 이메일로만** 발송됩니다. |

> ⚠️ **가장 헷갈리는 부분**: Resend에 등록하는 도메인은 **메일 보내는 주소**(`noreply@내도메인`)이지,
> 앱을 배포한 주소가 아닙니다. 둘은 별개이고, 배포하지 않아도 도메인 인증은 할 수 있습니다.

## 6. 배포하기 (Vercel)

> ⚠️ **먼저 알아야 할 것**: Vercel에는 **웹사이트만** 올라갑니다.
> **얼굴 인식 서버(Python)는 Vercel에 못 올립니다.** 아래 6-1을 꼭 읽어주세요.

### 6-1. 얼굴 인식 서버는 어디에?

`deepface-api` 는 TensorFlow와 PyTorch를 쓰는 **항상 켜져 있는 프로세스**입니다.
메모리가 2GB 가까이 필요하고, 시작할 때 모델 100MB를 내려받습니다.

Vercel의 서버리스 함수는 이런 걸 감당하지 못합니다 (용량 제한, 요청마다 새로 시작).
**별도 호스팅이 필요합니다.**

| 선택지 | 특징 |
|---|---|
| **Hugging Face Spaces** | 무료 CPU 16GB. 머신러닝 서버용이라 이 용도에 가장 잘 맞습니다. |
| Railway / Render | 간단하지만 무료 한도가 작아 메모리가 모자랄 수 있습니다. |
| 직접 서버(VPS) | 가장 자유롭지만 관리가 필요합니다. |

어디에 올리든 **주소를 Vercel 환경변수 `DEEPFACE_API_URL` 에 넣어야** 합니다.

```
DEEPFACE_API_URL=https://내-얼굴서버-주소/represent-liveness
```

이 값이 없으면 `http://localhost:5005` 를 찾다가 실패합니다. 배포된 웹사이트에서
localhost는 **서버 자신**을 가리키므로 절대 연결되지 않습니다.

### 6-2. Vercel에 웹사이트 올리기

1. GitHub에 푸시 (이미 되어 있습니다)
2. [vercel.com](https://vercel.com) → **Add New → Project** → 이 저장소 선택
3. **Environment Variables** 에 아래를 등록

   | 이름 | 값 |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | `.env.local` 과 동일 |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | `.env.local` 과 동일 |
   | `SUPABASE_SERVICE_ROLE_KEY` | `.env.local` 과 동일 |
   | `ATTENDANCE_TOKEN_SECRET` | `.env.local` 과 동일 |
   | `DEEPFACE_API_URL` | 6-1에서 올린 서버 주소 |

4. **Deploy**

> HTTPS는 Vercel이 자동으로 붙여줍니다. 카메라를 쓰려면 필수인데 따로 할 일이 없습니다.

### 6-3. 배포 후 반드시 바꿔야 하는 것

```
Supabase → Authentication → URL Configuration → Site URL
```

여기가 `http://localhost:3000` 이면, **확인 메일 링크가 localhost를 가리킵니다.**
참여자가 자기 폰에서 그 링크를 누르면 자기 폰의 localhost로 가서 아무것도 안 뜹니다.

배포한 주소(예: `https://facegate.vercel.app`)로 바꿔주세요.
**Redirect URLs** 에도 같은 주소를 추가합니다.

### 6-4. 배포 전 점검표

- [ ] 4개 마이그레이션을 전부 실행했는가 (`scripts/verify-supabase.mjs` 로 확인)
- [ ] 얼굴 인식 서버를 별도 호스팅에 올리고 주소를 확인했는가
- [ ] Vercel 환경변수 5개를 모두 넣었는가 (특히 `DEEPFACE_API_URL`)
- [ ] Supabase **Site URL** 을 배포 주소로 바꿨는가
- [ ] SMTP를 붙이고 **Confirm email** 을 켰는가
- [ ] `SUPABASE_SERVICE_ROLE_KEY` 에 `NEXT_PUBLIC_` 을 붙이지 않았는가 ← 붙이면 얼굴 데이터가 전부 샙니다

## 7. 보안 — 무엇을 어떻게 막고 있나

얼굴 데이터는 **개인정보보호법상 민감정보**입니다. 비밀번호는 바꿀 수 있지만 얼굴은 못 바꿔요.

### 7-1. 조직끼리 완전히 분리

다른 조직 사람과 얼굴이 비교되면, 그 순간 **남의 출석이 찍힙니다.**
그래서 모든 조회에 조직 조건을 강제하고, 실수로 빠뜨리면 아예 오류가 나게 만들었습니다.

`scripts/verify-org-isolation.mjs` 로 확인합니다 (임시 조직을 만들었다 지웁니다):

```
✅ 다른 조직의 소속·데이터가 보이지 않는다
✅ A 조직 사람의 얼굴이 B 조직에서 매칭되지 않는다
✅ 같은 얼굴이 A 조직에서는 매칭된다 (대조군, 거리 0.000000)
✅ 로그인 사용자 권한으로 얼굴 데이터를 읽을 수 없다
```

> **대조군을 같이 넣은 이유**: "매칭이 안 된다"만 보면 격리가 된 건지 매칭이 고장 난 건지
> 구분할 수 없습니다. 같은 얼굴이 자기 조직에서 정확히 잡히는 것까지 봐야 합니다.

### 7-2. 다른 사람의 얼굴 데이터가 새어나가지 않게

예전에는 출석 화면이 **등록된 사람 전원의 얼굴 데이터를 브라우저로 받아서** 비교했습니다.
지금은 **내 얼굴 하나만 서버에 보내고 결과만 받습니다.** 비교는 서버가 합니다.

### 7-3. 출석 위조 막기

예전에는 `userId` 만 보내면 출석이 기록됐습니다. 즉 **카메라 앞에 서지 않고도**
명령어 한 줄로 출석을 찍을 수 있었어요.

지금은 얼굴 비교에 성공했을 때만 서버가 **서명된 증표**를 발급하고, 그 증표가 있어야 기록됩니다.

```
가짜 시도: userId만 보냄        → 401 거부
가짜 시도: 아무 문자열이나 보냄   → 401 거부
다른 조직의 증표를 씀            → 403 거부
진짜: 얼굴 비교 통과 후 증표     → 201 기록됨
```

### 7-4. 권한 확인을 두 번 하는 이유

- `proxy.js` — **로그인했는지**만 확인
- 각 화면·API — **어느 조직의 관리자인지** 다시 확인

한 곳에서만 검사하면, 그 한 곳이 뚫렸을 때 남는 방어선이 없습니다.

## 8. 실험 결과 — 진짜로 막히는지 해봤습니다

### 8-1. 폰 화면으로 속이기 (2026-08-04, 6회 시도)

폰에 얼굴 사진을 띄우고 카메라에 들이댔습니다.

| # | 조건 | AI 판정 | 결과 |
|---|---|---|---|
| 1 | 평소 밝기·정면 | **진짜라고 착각** | 얼굴이 안 맞아서 겨우 차단 |
| 2 | 최대 밝기 | 가짜 | 차단 |
| 3 | 최소 밝기 | 얼굴 인식 실패 | — |
| 4 | 15~20° 기울임 | 가짜 | 차단 |
| 5 | 낮은 밝기 | 가짜 | 차단 |
| 6 | 1번과 같은 조건 | 가짜 | 차단 |

**결론: 6번 중 1번(약 17%) AI가 폰 화면을 진짜 얼굴로 착각했습니다.**

더 나쁜 건, **1번과 6번은 조건이 똑같은데 결과가 갈렸다**는 점입니다.
"이런 상황만 조심하면 된다"가 없다는 뜻이에요.

1번이 그나마 막힌 것도 얼굴 거리가 **0.3049**로 기준선 0.30을 **0.0049 차이**로 넘겼기 때문입니다.
운이 좋았던 거지, 제대로 막은 게 아닙니다.

### 8-2. 예상이 빗나간 것: "사진은 안 흔들린다"는 착각

원래 이런 논리가 있었습니다. *"진짜 사람은 미세하게 움직이고, 사진은 가만히 있다."*

실제로 재보니 **정반대**였습니다.

| 상황 | 흔들림 점수 |
|---|---|
| 진짜 얼굴 | **2.458** |
| 폰을 손에 들고 | **13.947** ← 훨씬 더 흔들림! |

**손이 떨리기 때문**이었습니다. 사진은 가만히 있어도 **폰을 든 손**이 움직여요.
이 지표를 쓰면 오히려 공격을 도와주는 셈이라, 판정에서 뺐습니다.

### 8-3. 그래서 어떻게 고쳤나

| 고친 것 | 내용 |
|---|---|
| 기준선 조정 | 0.30 → **0.25** (여유 0.0049 → 0.22로 넓힘) |
| 흔들림 지표 제외 | 판정에서 빼고 기록만 남김 |
| 고개 돌리기 시험 도입 | 사진은 고개를 못 돌립니다 (§9) |

> **눈 깜빡임을 필수로 하지 않은 이유**: 스캔 시간이 1.5초인데 사람은 평균 3~4초에 한 번
> 깜빡입니다. 필수로 걸면 **진짜 사람이 못 들어옵니다.** 실제 성공한 스캔에서도
> `blinkDetected: false` 였어요.

### 8-4. 계산이 정확한지 확인

데이터베이스를 파일에서 Supabase로 옮기면서, 얼굴 거리 계산도 SQL로 넘어갔습니다.
계산이 달라지면 기준선 0.25가 의미를 잃으므로 대조해봤습니다.

```
동일 벡터      JS=0.000000  SQL=0.000000
잡음 ±1.00     JS=0.145681  SQL=0.145681   차이 0.000000042
```

✅ 같습니다. 기준선 0.25는 그대로 유효합니다.

## 9. 고개 돌리기 시험 (능동 챌린지)

AI 판정이 17% 확률로 틀리니, **다른 방식의 문**을 하나 더 달았습니다.

사진은 고개를 돌릴 수 없습니다. 그래서 **지시한 대로 고개를 돌렸는지** 확인합니다.

```
"고개를 왼쪽으로 살짝 돌려주세요"    ← 5초 안에
"정면으로 돌아온 뒤 오른쪽으로"      ← 다시 5초 안에
```

### 순서를 매번 바꾸는 이유

순서가 항상 같으면, 왼쪽 사진·오른쪽 사진을 미리 준비해서 순서대로 들이대면 통과합니다.
그래서 **4가지 중 하나를 무작위로** 고릅니다.

```
좌→우   우→좌   좌→좌   우→우
```

미리 준비한 각본이 맞을 확률이 **25%로 떨어집니다.**

**같은 방향이 연속되는 경우**(좌→좌)도 일부러 넣었습니다. 이때는 **먼저 정면으로 돌아온 것을
확인한 뒤에야** 다음 검사를 시작합니다. 안 그러면 고개를 돌린 채로 가만히 있어도 통과해버려요.

### 이걸로 다 해결됐나요? — 아니요

솔직하게 적습니다. 이건 **싼값에 막을 수 있는 것만 막은 것**입니다.

| 막은 것 | 못 막은 것 |
|---|---|
| 미리 정해진 순서로 사진 두 장 들이대기 | **화면 자체를 기울이기** — 평면을 기울인 것과 진짜 얼굴이 돌아간 것을 2D 좌표만으로는 구분 못 함 |
| | **고개 돌리는 영상 미리 녹화해서 재생** — 지시가 뜨는 순간 맞춰서 재생하면 통과 |

제대로 막으려면 **3D 얼굴 구조를 보는 검증**(예: MediaPipe Face Mesh)이나
지시 타이밍 무작위화가 필요합니다.

## 12. 문제가 생겼을 때

| 증상 | 원인과 해결 |
|---|---|
| `Failed to load PyTorch C extensions` | Python이 3.12 이상. **3.11로 venv를 다시 만드세요** (§4-3) |
| venv 만들 때 `Permission denied` | 서버가 이미 돌고 있어서 파일을 잡고 있음. 서버 창에서 `Ctrl+C` 후 재시도 |
| `Invalid supabaseUrl` | `.env.local` 에 `<project-ref>` 가 그대로 남아 있음 |
| `Invalid API key` | 열쇠 종류를 착각했거나 잘려서 복사됨 (§4-1 경고) |
| `Error sending confirmation email` | 메일 발송 설정 문제. §5 참고 |
| `column reference ... is ambiguous` | `0004` 마이그레이션을 실행하지 않았음 |
| 카메라가 검은 화면 | 가상 카메라가 잡힘. 화면 아래 **드롭다운에서 다른 카메라 선택** |
| 로그인은 되는데 대시보드가 안 보임 | 참여자 계정임. 관리자는 `/admin/login` 으로 |
| 로그인 후 `/start` 가 뜸 | 소속 조직이 없음. 조직을 만들거나 인증코드를 입력 |
| 배포 후 `DeepFace 서버 꺼짐` | `DEEPFACE_API_URL` 미설정 (§6-1) |
| 확인 메일 링크가 안 열림 | Supabase **Site URL** 이 localhost (§6-3) |
